# 请求、缓存与渲染性能

本轮优化不改变来源数据格式，不增加运行时依赖，也不写入真实会话来做基准。

## 刷新与状态入口

- `refreshWorkspace(scopes)` 合并同一批失效范围；运行期间的新变更最多积累为下一轮，各轮不并发执行。元数据部分失败时仍尝试其他刷新，最后报告失败。
- `query` 表示前台查询改变，立即使旧查询、详情和统计请求失效，统一清理分页；`sessions` 表示后台数据更新，保留阅读上下文。`facets`、`diagnostics`、`stats` 各自控制刷新范围。
- 后台更新发生在非列表视图时标记列表待刷新，进入列表再读；统计不在当前视图时只标记失效，进入统计页后查询。列表接口直接返回筛选后的 `total`，计数不再依赖统计接口。
- 主题与语言变化只重绘已有数据；进入已缓存的统计页也重绘主题色，不为外观变化重新查询后端。
- `workspace-state.js` 承载查询失效、会话选择和权威列表响应的状态转换；DOM 与请求调度仍由应用层协调。

## 只读调度与取消

带取消信号的列表／搜索、详情、统计及 facets 请求按通道串行。一个通道最多保留一个执行中请求和一个最新待执行请求。无信号读取、批量导出及写操作不参与替代。

前端通过 `requestId` 标记可取消的读取，AbortSignal 触发 `cancel_read_request`。后端只对明确允许的 GET 路由注册令牌，写操作不注册。令牌在任务结束后清理，提前到达的取消通知有容量与过期限制。

取消是协作式的：任务开始前、全文搜索逐行读取、通用 JSONL 解析循环以及详情解析前后检查令牌。专用来源适配器的单次解析和底层文件／SQLite 调用不能被强制中断，会在返回后的检查点退出。取消的任务不会发布结果或回填详情缓存；事务写入不受影响。

## 详情锁与缓存

普通详情读取分为锁内快照、锁外解析和锁内缓存回填。锁外阶段包含文件读取、解析及响应体积估算；快照不复制搜索全文。回填检查缓存代次、记录路径、来源与摘要；主文件及 WAL 在读取期间变化时重新读取，最多尝试两次。

搜索上下文读取暂沿用原路径；永久删除需要的详情读取仍在写操作锁内，保持删除前校验与写回边界。详情缓存继续使用原有 64 MiB 上限。

## 消息渲染

- 按稳定消息键和内容／语言／检索状态签名复用卡片，新增或变化的消息才重建；工具结果共同参与签名，避免按钮持有过期参数。
- 正则高亮是异步修改 DOM 的流程，当前采用保守重建，避免重复高亮；普通查询变化也使签名失效。
- 初次渲染每新增 16 张卡片或本批耗时达到 8ms 时让出执行权；继续前检查取消和当前会话。单张卡片的解析不强行切断。
- Markdown 使用 LRU 缓存，最多 128 项、估算 4 MiB；缓存中保存无事件处理器、无高亮的 DOM 克隆。容量估算计入文本及节点数量，不等同于实际堆内存。
- 附件观察器只释放脱离文档的节点，复用卡片保留懒加载。原始事件页按需生成，默认阅读对话时不构建隐藏事件卡。

## 合成基线与实机采样

运行 `node scripts/benchmark-ui-work.mjs`，不会连接 Tauri 或读取会话文件。其基线是未合并请求、逐条全量重建的合成工作量，不是历史版本的桌面运行成绩。

| 场景                                | 未合并／全量基线 |          当前合成结果 |
| ----------------------------------- | ---------------: | --------------------: |
| 首个读取未完成时提交 100 个候选读取 |       100 次提交 |              2 次提交 |
| 同批触发 100 次刷新                 |           100 轮 |                  1 轮 |
| 800 条消息只改变最后一条            |       800 张重建 | 更新计划要求重建 1 张 |

脚本同时输出更新计划的实际执行时间，该时间随机器与运行状态变化，不作为固定门槛。

设置页“复制诊断”附带 `ui_performance` 聚合指标：IPC 次数及耗时、刷新轮数、Markdown 解析／命中、卡片重建／复用、批次耗时和 DOM 节点数。每项只保留最近 128 个数值用于 P95，累计计数和均值覆盖当前进程；不包含查询词、文件路径或正文。

需要后端实机采样时，在启动前设置 `ALLSESSIONS_PERF=1`，日志输出固定阶段名与微秒耗时，包括 IPC 总耗时、详情锁等待、快照和解析。默认不输出性能日志。

仍需在真实桌面上用脱敏大样本测量首次打开、连续搜索、实时追加、主题切换和窗口缩放；不能用上述调度工作量推断真实 CPU、内存或帧率提升比例。
