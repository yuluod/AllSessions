# 来源架构

AllSessions 的运行时实现位于 `src-tauri/src`。前端只消费统一 JSON 契约，不判断来源文件格式。

## 模块边界

- `sessions.rs`：来源声明、文件发现、格式解析、统一摘要/详情、筛选、搜索和统计。
- `sessions/gemini.rs`：Gemini 日志流式扫描、逐文件摘要缓存、跨文件会话合并和按需详情解析。
- `cache.rs`：以路径、文件大小和修改时间为指纹的 SQLite 摘要/搜索缓存；负责导入旧版 JSON 索引。
- `config.rs`：设置对话框持久化的应用配置（`AllSessions/config.json`），按来源覆盖根目录列表，优先级高于环境变量。
- `watcher.rs`：监听来源目录，去抖后刷新索引并发送 Tauri 事件；设置保存后通过 `rewatch` 重挂监听。
- `backend.rs`：前端唯一 IPC 边界，将稳定的请求契约路由到 Rust 领域模块。
- `maintenance.rs`：隔离的 Codex Provider 预览、写入、备份和字段级回滚。

## 来源职责

每个来源实现必须：

- 只在声明目录内发现和监听文件，且不跟随符号链接越界。
- 将数据归一化为 `summary`、`conversation_messages` 和 `raw_events`。
- 摘要使用流式解析，不能把完整大会话装入内存。
- 搜索文本、详情消息、原始事件和详情缓存都必须有明确上限。
- 单个损坏文件不能阻止其他来源启动。
- 使用 `${source_kind}:${id}` 组合键避免跨来源 ID 冲突。

Gemini 的会话可能跨多个 `tmp/*/logs.json`，因此按 `sessionId` 聚合。每个日志文件只缓存有界摘要贡献，完整消息和原始事件在用户打开会话时重新流式读取，并应用与其他来源相同的首尾窗口；其他当前来源是一文件一会话。

来源列表会保留尚不存在的声明目录，以便后续刷新发现新创建的数据；监听器会回溯到最近的现有父目录，但不会监听用户主目录或文件系统根。设置对话框保存根目录后会重建来源并重挂监听，无需重启。每个 Claude 根目录会同时注册 `projects` 与 `sessions` 布局；旧版 `history.jsonl` 只会在解析对应旧版会话详情时作为补充数据读取，它本身不是独立监听目标。

同一类来源可声明多个根。根列表按 `config.json` 设置（设置对话框实时生效）→ `*_SESSIONS_DIR` 环境变量（启动时读取一次，路径列表，支持 `~` 展开）→ 系统默认路径的顺序解析，逐来源独立判定。多根按声明顺序去重：同一物理文件只索引一次（归属首个前缀匹配的根）；相同 `${source_kind}:${id}` 出现在多个根时保留首个根的记录，`_key` 格式保持稳定以兼容前端已保存状态。

## 增加新来源

1. 在 `configured_sources` 声明根目录、显示名称和格式；根来自路径列表环境变量时经 `sources_from_paths` 展开。
2. 添加精确发现规则与解析分支，复用统一消息/摘要工具。
3. 为元数据、消息、工具调用、损坏输入、大文件截断和 ID 冲突添加脱敏 Rust 测试。
4. 确认文件变化会刷新缓存并通过 `sessions-changed` 通知前端。
5. 更新 README 支持矩阵与 `docs/sources` 中的来源边界。

前端来源筛选来自 `facets.sources`，新增来源不应增加前端固定数组。
